# 一个大模型工程师的诞生

**武辰 著 · 清华大学出版社审校中**

如果你想做大模型算法工程师，最让人焦虑的，往往是不知道到底要学多少才算够。网上的学习路线一张比一张长，看完反而更慌了。但很多人入职以后才发现，就算路线图上的东西全学完了，真坐到工位上，每天花时间最多的，是洗数据、写标注说明书、和产品经理对齐需求、接手同事留下的代码，这些事路线图上一般不会写。

这本书想把两件事放在一起讲：**一条从原理到工程的完整技术路线，还有入职以后才会知道的真实日常**。它从计算机基础和必要的数学讲起，一路讲到 Transformer、微调、对齐、RAG、Agent、部署和评估；后半本写数据工程、团队协作、做项目和求职。

这个仓库放着当前的书稿目录、八份样章、样章对应的代码和配套练习，你可以先读几节，看看这样的讲法适不适合你。

## 这本书是怎么讲的

写第一本书《大白话概率论》时，我给自己定过一个要求：**用大白话讲，不跳步**。这本书也一样。遇到重要的概念，我不会只给一个定义就往下走，会尽量拿一个很小的例子，**带你手算一遍**：注意力分数到底怎么算，损失函数怎么从几个数字算出来，显存为什么会突然不够用。跟着算过一遍，那些看起来抽象的概念，就变成了一笔能算清楚的账。

这本书也不默认你是科班出身，或者已经熟悉深度学习、Linux、CUDA 这些东西。该补的背景我会补，但只补够用的那一部分：能让你接着往下读，在工作和面试里不露怯，就够了。和主线无关的推导，我尽量不放进来吓人。

为了让你读完真能用上，很多小节里有几个固定的栏目。**踩坑框**讲新人最容易掉进去的坑；**面试框**把刚学的技术点放到面试官真会问的问法里；**自检清单**帮你确认自己是不是真懂了；**Python 交互实验室**用很小的代码，让你亲手验证一个现象。所以面试不是最后几章才出现的东西，你学每一个技术点的时候，都会顺手看到它可能会被怎么问。

从第六部分开始，我写了很多数据工程、团队协作和求职的内容。这些事情占了算法工程师一半以上的精力，却基本不会出现在任何一门课里。我刚入行的时候也没人告诉我，都是自己摸爬滚打才弄明白的。编辑听说我要写职场，第一反应是问我会不会写成心灵鸡汤。书里写的都是具体的场景：比如测试工程师提了一条 bug，你觉得不算 bug，你们俩怎么争、怎么把标准对齐、最后怎么收场。

大模型变化很快，我写下这些字的时候，某个框架可能已经在准备下一次更新了。所以我有意把重心放在不容易过时的东西上：原理、想问题的方式和做事的方法。

## 适合谁读

如果你想做大模型，或者正在转行做大模型，这本书想给你一条完整的路：前半本讲原理和工程，后半本讲入职以后每天要面对的事。还在学校的同学，可以把书里的面试框，还有第七到第九部分的做项目、找工作，当成求职准备来读。
